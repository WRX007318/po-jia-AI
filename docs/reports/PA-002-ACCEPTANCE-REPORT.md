## 已实测

- 硬件：Intel i5-10400F（6 核/12 线程）、32 GiB RAM、RTX 3060 12 GiB；NVIDIA 驱动 512.15（CUDA 11.6）。未改动驱动。采用 llama.cpp 官方 b12774 Windows Vulkan x64 构建，避免 CUDA/驱动升级风险。
- 模型已在 `D:\PoJiaAI\models\inkling2mini`，约 13.34 GB GGUF + 639 MB mmproj。没有重复下载。HF 固定 revision 的 tree API `lfs.oid` 与本地完整文件 SHA-256 一致；Xet Hash/Resolve ETag 是对象标识，不可当内容 SHA256。模型启动前逐块 SHA256 校验；缺文件/尺寸/hash 错误会阻止服务标记 ready。
- llama-server 确实加载模型及视觉投影，`/health` 返回 ok，`/props` 的模型路径与 vision modality 经过检查。启动时启用 64-token reasoning budget 后，中文、代码、结构化 JSON 和合成图片识别请求都返回了最终正文；视觉服务严格解析 JSON，拒绝无效或截断结果。
- 真实图片 Worker 端到端：独立 Python 子进程读取合成业务列表图，调用共享本地模型，写入 SQLite；任务 `completed`、唯一新增数 1、检查点更新，分类为“业务订单管理”，OCR 为“业务订单管理 / 订单列表 / 共 2 条记录”，标签“订单管理 / 业务列表”，待人工审核标志保留。
- 性能矩阵（均为真实 llama-server + 相同短中文回答，首 Token 延迟以服务端 prompt eval 总时间计；系统资源是生成完成时快照，受其他桌面应用影响）：

  选用 12 / 2048 / 6 作为默认配置：本轮短答生成速度最快，Context 保留 2048，且 GPU 仍有约 3.4 GiB 可用。不同配置的系统级 GPU 数值波动较大，不能解读为模型独占显存精确值；工作集也会受缓存/访问历史影响。未尝试 16 层或 4096 Context，以免在 12GB 卡上压低桌面安全余量。

- `python -m unittest discover -s tests -v`：7 项通过；包含 hash 拒绝启动、视觉失败不推进检查点，以及失败后继续处理时不漏计已导入但尚未标注的唯一样本。Python 编译和 `git diff --check` 通过。

## 失败与未验收（不得视为 PA-002 完成）

本机模型的 reasoning 段会占用大量输出。只设 `reasoning_effort=none` 时出现过截断/超时；加入 `--reasoning-budget 64` 和请求级预算后，四类文本/图片探针返回了内容，且真实 Worker 完成了视觉 JSON 解析和 SQLite 入库。非最终回答、无效 JSON 和超时都不会被当作有效标注或推进检查点。结构化 JSON 的一条通用分类探针曾把普通网页保守标成需要人工复核（误报）；视觉分类需进一步用人工标注集校准。

未取得可确认授权的真实大麦/WDA 普通业务截图或脱敏历史数据，本次只用合成图验收，不声称大麦页面识别精度已通过。Worker 可检测挑战并要求人工复核，但未用真实安全验证页面测试。性能矩阵覆盖 8 与 12 GPU 层、1024 与 2048 Context、4 与 6 线程；没有测试 16 层及 4096 Context。

## PA-002 工程整改

- 用固定 Hub revision 的可信 `lfs.oid` 内容 SHA256 修复 Xet ETag 误判，保留独立 Xet ID 元数据；已下载模型复用。
- 默认数据/运行目录统一指向 `D:\PoJiaAI`，支持 `POJIA_HOME` 覆盖；启动检查模型文件及 SHA256。
- 增加服务 `/props` 模型路径与视觉能力核验、非空最终回答保护、结构化 JSON 入口、Tk 流式回答。
- 增加独立本地视觉 Worker、单实例锁、JSON 控制文件、暂停/继续/停止、失败时保留同一检查点、SQLite 哈希去重、OCR/视觉 JSON 标注与人工复核标志。窗口关闭不会停止已运行的 Worker 或模型服务；用户可在任务界面单独停止调度器。暂停/失败恢复、停止边界及重复图片计数有回归测试。传统 Tesseract 为可选项；本机未安装时使用本地 VLM OCR。
- 服务默认加入 64-token reasoning budget；VLM 限定输出数量和长度，增加超时恢复检查点；烟测会校验 JSON 可解析性。
- `launch.pyw` 将应用 `app` 目录加入导入路径，修复桌面快捷方式 GUI 启动问题。
