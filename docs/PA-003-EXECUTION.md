## 0 体检
采集当前可用物理内存、可用显存、桌面进程内存 TOP5、llama-server 完整命令行、--version/build、驱动版本。可用内存低于 16 GiB 提示人工关闭桌面负载，不阻塞阶段 1。配套 scripts/pa003-baseline.ps1 可在本机执行，原始输出仅存本机；据真实输出生成 docs/reports/PA-003-BASELINE.md，commit。

## 1 显存与内存整形
- IQ3_S：--n-gpu-layers 99，--n-cpu-moe（或 -ncmoe）从 8 起每轮减 1；若首轮 OOM，从更高 CPU MoE 层数重新建立可运行起点。目标总显存使用 9500–10500 MiB。
- 记录每轮参数、实际 GPU/CPU 张量分布、显存、可用 RAM、tok/s、异常及日志路径。
- RAM 低于 3 GiB 回退一级；GPU OOM、加载失败或资源不足不得继续降低 CPU MoE 层数，回退并记录。目标区间不可达也据实保留最佳可运行配置。

## 2 引擎参数
在阶段 1 基线上追加：GPU 视觉投影卸载、-fa on、--cache-type-k q8_0 --cache-type-v q8_0、-c 4096、-t 6 --threads-batch 6、-np 1、--jinja。
先以当前二进制 --help 核对实参；上游 llama.cpp 文档列出 --mmproj-offload/--no-mmproj-offload，默认启用，用户任务中的 --mmproj-use-gpu 是待核对的候选名，不能盲传或假定之前视觉塔一定在 CPU。以加载日志核实实际设备。上游参考：https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md
实测纯文本、单张图、合法 JSON，记录首 token、总耗时、生成速度、内容和资源快照。缓存类型不兼容则记录并回退，不伪造成功。

## 3 驱动与引擎
- 记录升级前 Vulkan 基线。评估官方支持 RTX 3060 的 NVIDIA 550 以上或满足选定 CUDA 构建最低要求的驱动，保留原驱动安装包/回滚路径、旧 Vulkan 二进制与配置。
- 在本机执行可回滚升级并换兼容 CUDA x64 构建；重启如有必要，保存任务检查点，复测三项及原有程序兼容性。安装要求管理员/UAC 或用户交互时如实报告，并继续能做的独立测试。
- CUDA 不如 Vulkan 时回退后实测确认；区分运行时回退与驱动回退。不得无依据宣称升级成功。

## 4 Reasoning
依次试验：API chat_template_kwargs.reasoning_effort=none；system prompt 要求只输出最终答案；max_tokens=512 及检查双换行分隔。记录 reasoning tokens/耗时与最终答案是否完整。
可在独立测试脚本分析输出，不改 app/ 前端；界面隐藏或字符串截断不会减少后端实际生成时间，也不能当作完整答案或合法 JSON。可核对构建支持的 reasoning budget/模板参数，理由记入 DECISIONS.md。

## 5 视觉链路
合成普通业务列表图 <=200 KB，长边 1024，记录首个实际 token、首个可见答案 token、总耗时、返回内容。20 秒未完成则记录失败并取消/清理本轮，长边降 768 复测。再次失败保存 RAM/VRAM 快照与日志。只有正确、完整识别才算通过。

## 6 验收（不修改门槛）
| 项 | 门槛 |
|---|---|
| 生成速度 | >= 8 tok/s |
| 图片识别 | < 20 s 返回正确完整结果 |
| JSON 结构化 | < 30 s 且合法 |
| 显存占用 | 9500–10500 MiB |
| 中文短答 | 通过 |

切换模型重跑阶段 1–6，已完成驱动安装则复用，不重复安装。达标时 IQ2_M 定为生产候选，IQ3_S 备用；仍不达标则记录在当前实测配置下本机不适合该 26B MoE 模型的性能目标，写入 DECISIONS.md。不能仅凭两种量化外推所有 26B 模型。
注意：现有 app/runtime.py 固定 IQ3_S 文件路径和 ready 判定；在本任务禁止修改 app/ 的前提下，IQ2_M 只能由独立基准启动配置验证，不能宣称已接入桌面生产入口。实际桌面接入另列待授权任务，不重命名权重欺骗校验。
