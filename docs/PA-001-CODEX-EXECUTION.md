# PA-001 — 本地 AI 工作台统一实施任务

状态：待本机 Codex 执行。此文档整合模型部署、桌面交互、编程 Agent、独立视觉采集与验收，不代表功能已完成。

## 1. GitHub 工作流
- 主仓库 https://github.com/WRX007318/po-jia-AI 。在本机通过已授权的 GitHub 连接或 git/gh 读取最新 main、README.md、models/catalog.json、deployment/README.md、security/README.md 和本文件。
- 若尚无本地副本，克隆到独立项目目录；已有副本则先检查 git status，保留未提交的用户修改，禁止强制重置或覆盖。以最新基线建立实施分支，例如 feat/pa-001-local-workbench；按里程碑提交、推送并创建 PR，保留测试日志与 SHA。权限不足则报告准确阻塞，不得虚构提交。
- 仓库公开，仅提交自有源码、许可允许的第三方材料、配置模板、合成/脱敏样本和报告。模型权重、真实截图、数据库、个人设备配置及密钥留在本机。不要修改其他仓库或既有程序。
- 优先复用成熟开源组件，核查来源、许可、固定版本、完整性和真实兼容性，不盲目执行不可信下载脚本。

## 2. 模型及硬件
- 选定性价比候选 Inkling 2 Mini AD-IQ3_S，而非大型旗舰模型。来源 https://huggingface.co/AtomicChat/Inkling-2-Mini-Uncensored-GGUF ；运行时候选 https://github.com/ggml-org/llama.cpp 。
- 先读取本机硬件审核（CPU、RAM、GPU/VRAM、磁盘、驱动），确认完整 GGUF、匹配 mmproj、实际文件名称、大小、校验值、固定 revision、运行时版本和许可。若首选不适配，评估 AD-IQ2_M；若仍不足则停止下载并报告实际原因。
- 完成安装、文本及图片真实推理，默认本机回环 API，编程及视觉共享同一模型实例；设置队列、超时、取消、优先级和资源上限。不得以服务进程存在代替实际推理成功。
- 模型及运行时保存在独立本地目录；必要依赖经核验后安装，不影响既有业务程序。

## 3. Windows 桌面工作台（打开即用）
- 主交付是可双击启动的中文 Windows 桌面应用，不是静态网页。建立桌面快捷方式；正常使用无需 CMD、PowerShell、Python 或手动启动服务。
- 首次启动提供模型与环境检查、下载/校验进度、存储目录、故障诊断和可取消的引导。后续自动连接模型、数据库、恢复配置和历史记录；清晰区分加载、就绪、失败和停止状态。
- 导航：AI 对话、编程工作台、视觉工作台、视觉任务、视觉数据库、模型管理、资源监控、设置/日志。支持聊天流式输出、停止生成、代码高亮、图片上传、持久化会话；编程界面含项目选择、文件树、差异预览、受控终端、审批、测试、回滚。
- 视觉界面含图片预览、识别结果、OCR、页面分类、标签修正及入库；任务界面有开始/暂停/继续/停止、来源选择、采集上限、运行进度、异常日志。数据库界面有检索、预览、审核、去重及导出。
- 各开放按钮必须接真实后端；未完成项禁用并说明原因，不得使用模拟数据冒充生产结果。关闭及重启后历史和设置保持；可显式停止任务和释放模型资源。

## 4. 独立视觉 Agent
- Codex 只负责搭建及验收；本地任务调度进程在 Codex 退出后独立运行，不需云端模型逐次下令。用户从桌面面板设定已授权的采集范围、设备/本地样本目录、时间与数量限额。
- 优先处理已有脱敏截图和自有测试环境；经授权可通过只读设备截图接口获取普通页面，或监听人工浏览时提供的截图。不得自行操作第三方账户、购买或支付、批量切号、绕过访问限制或自动求解安全验证。遇验证页面标记需要人工处理，不收录挑战内容。
- 混合流水线：截图导入 → 脱敏及哈希去重 → OpenCV/局部 OCR → 复杂画面调用 Inkling → JSON schema 校验 → 页面类型与元素标注 → 人工复核队列 → SQLite 入库 → 基准及回归测试。
- SQLite 记录样本 ID、相对路径、哈希、屏幕尺寸、脱敏设备/应用版本、分类、OCR、模型版本、标注、审核、耗时；保存任务状态、重试及检查点。样本数量不足据实报告，禁止重复截图虚增。
- 第一阶段目标：普通页面类别每类约 10 个有效样本、总计争取 200 个去重样本；以现有授权数据为限。训练集、验证集按会话/设备或来源分组避免近重复泄漏；人工校验后统计准确率，模型自报置信度不当作真实准确率。
- 数据积累用于模板、检索、分类及策略改进，不等于模型权重训练。支持离线处理、暂停/恢复、断连安全暂停、资源限制、错误隔离及幂等入库。

## 5. 编程 Agent
- 可在授权本地项目内读取代码、生成差异、运行批准的命令和测试，记录过程及结果。默认不接触生产账户、敏感信息或真实交易；限制文件和终端权限，敏感操作须审批；模型输出不可直接无条件执行。
- 优先测试普通多文件工程、Bug 修复、单元测试、结构化工具调用及失败恢复。不能将文本对话冒充自主编程完成。

## 6. 验收及交付
- PA-A：本机硬件审核、模型文件校验、真实文本/图片推理。
- PA-B：桌面启动入口、真实按钮、会话持久化、关闭再启动、离线使用。
- PA-C：编程任务、真实文件差异、测试及回滚记录。
- PA-D：独立视觉任务、样本入库、审核、去重；关闭 Codex 仍运行、断网处理本地样本、设备断连暂停、重启恢复。需人工设备操作的测试单独标为待测。
- PA-E：比较全屏 OCR、局部 OCR、OpenCV、大模型及混合引擎；记录样本量、平均/P95 延迟、准确率、峰值 RAM/VRAM、生成速度及并发稳定性。没有实测数据就标未验证。
- PA-F：Windows 可执行程序或安装包、桌面快捷方式实际位置、使用说明、源码、依赖锁定、自动化测试、脱敏验收报告、PR 链接与 commit SHA、剩余阻塞。默认不将模型或本地安装包内的敏感文件提交至公开 GitHub。

按依赖关系实际执行；遇硬件、权限或外部资源阻塞，完成不受影响的部分并给出准确原因。禁止只交方案、静态面板或虚构测试。
